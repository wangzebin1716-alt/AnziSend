# AnziSend

**在电脑与手机之间收发文件。局域网内可以离线直传，身处不同网络时可以用身份码尝试连接。**

AnziSend 可以在家里传照片、在办公室交接大文件，也可以和校园网里的同学互传资料。两台设备在内网中能互相访问时，即使连着不同的 Wi‑Fi，或一台接网线，也能直接传输。临时借用一台电脑时，可以打开网页版收发文件。Windows 版还提供本地 AI，帮你分类整理收到的文件。

## 局域网直传的改进

AnziSend 的局域网直传基于 [LocalSend](https://github.com/localsend/localsend)。AnziSend 在此基础上改进了设备发现、传输选路和大文件续传。

| 改进 | 实际使用中有什么帮助 |
| --- | --- |
| 找到设备后继续补扫 | 沿用 LocalSend 的分阶段发现流程。组播或已知地址先找到一台设备后，仍会补扫局域网，帮助发现同网段里没有响应组播的其他设备。 |
| 多网卡与切网发现 | 默认纳入所有符合条件的 IPv4 网卡地址，限制并发扫描数。切换网络时，如果旧扫描仍在运行，会保留最新的刷新请求并在随后执行。 |
| 支持手动连接 | 自动发现不到时，可以输入接收设备的局域网 IP 地址和端口。适合已知地址、两端能互访的情况。 |
| 优先走局域网直连 | 对已经核对身份的设备，发送前优先验证局域网地址。局域网路径不可达时，如果有可用的跨网连接，可以在开始传输前改走该路径。 |
| 大文件断点续传 | 支持续传的设备之间，传输中断后可以从已保存的进度继续。重试时还可以尝试同一设备已确认的其他局域网地址。 |

在同一企业或校园内，办公 Wi‑Fi 与有线网络、不同 Wi‑Fi 之间只要允许设备互访，就可以使用局域网直传，无需互联网。

### build132 的局域网改进

- **离线连接码。** 自动发现不到设备时，可以在接收端显示连接码。Android 端可拍摄二维码，电脑可粘贴连接码。需要双方内网可达，接收端使用 HTTPS 和 IPv4。发起连接时会核对接收端的证书指纹。
- **按真实网段补扫。** 客户端读取 IPv4 网卡的子网掩码，每个接口最多探测 512 个地址，限时 12 秒。较大的网段可以使用连接码或手动输入地址直连。

## 实际怎么用

- **手机照片传到电脑**。在同一个可互访的内网里打开手机端和电脑端，从手机选择照片，确认接收方是自己的电脑。电脑接收后，可以在设置的接收目录里找到文件。
- **电脑之间交接一个项目**。两台电脑能在内网互访时，可以直接拖入项目文件夹发送。接收方先确认保存位置和剩余空间，传完再按文件数量或大小核对。桌面版提供接收记录和大文件续传功能。
- **把资料发给身处另一网络的人**。例如一台电脑在企业网，另一台在校园网。双方保持在线，交换身份码、核对设备指纹并添加好友，再用一个小文件确认这两张网络能建立直连。
- **临时电脑通过浏览器接收**。打开网页版并连接，把页面上的身份码发给对方。完成好友核对后接收文件，再从「收到的文件」下载到电脑。换浏览器或换浏览器用户时，可以先查看当前页面的身份码。

## 选一种传输方式

| 你的场景 | 用什么方式 | 开始前确认 |
| --- | --- | --- |
| 家里没接互联网，或在同一企业、校园的内网里 | 软件内局域网直传 | 两台设备能在内网互访。访客 Wi‑Fi 或设备隔离可能拦截连接。 |
| 一台在企业网，另一台在校园网，或两台设备在不同城市 | 用 12 位身份码查找对方，核对身份后尝试跨网直连 | 双方在线，使用支持跨网直连的版本。需要可达的 IPv6 连接，或成功建立 IPv4 打洞连接。 |
| 临时借用电脑，需要从浏览器收发 | 打开网页版，连接身份服务，选择已核对的在线好友 | 浏览器有自己的设备身份。能否传输取决于双方网络。 |

### 局域网直传

1. 在两台设备上打开 AnziSend，让设备接入可互访的内网。
2. 在设备列表找到接收方，核对设备身份。自动发现不到时，可以手动输入接收方的局域网 IP 地址和端口。
3. 选择文件或文件夹发送。接收方确认后，可以查看传输进度。桌面版可设置接收目录、查看接收记录和续传大文件。

### 跨网络直连

1. 双方打开 AnziSend 并保持在线。请对方提供 12 位设备身份码。
2. 在「身份码与好友」中查找对方。核对设备指纹并完成好友确认。
3. 从在线设备中选择对方并发送文件。

跨网络直连目前处于测试阶段。身份服务用于查找设备和协调连接，文件传输依赖设备间的直连。目前没有文件中继。运营商 NAT、企业防火墙、VPN 或手机热点都可能影响连接，出现「搜得到对方，但文件发不出去」时，可以检查双方网络是否允许直连。

### 网页版收发

打开网页版，点击「连接」，再用设备名称或身份码查找对方。核对身份并完成好友确认后，在「发送文件」选择在线好友。收到的文件可从「收到的文件」下载。网页版的身份和浏览器中保存的文件可能会随网站数据一起清除，收到重要文件后请及时下载。

## 从查找到收件，按顺序排查

| 看到的情况 | 先检查什么 |
| --- | --- |
| 局域网设备列表空白 | 两端都打开客户端，确认内网允许设备互访。如果一端是访客 Wi‑Fi，可以接入允许设备互访的网络再试。 |
| 按名称找不到对方 | 请对方打开当前使用的客户端或网页，确认已连接身份服务、允许查找，再用该端显示的 12 位身份码查找。 |
| 按名称搜出多台设备 | 用接收方提供的身份码锁定目标，并核对设备指纹后再发送。 |
| 找到对方，但网页版没有可发送的对象 | 确认好友申请已经处理、身份已经核对，并请对方保持在线。 |
| 双方在线，小文件也发不出去 | 如果在跨网使用，可以让双方接入同一个可互访的局域网，用客户端试传同一个文件。局域网成功时，再检查跨网一侧的 IPv6 可达性、NAT、VPN 或网络策略。 |
| 网页显示文件已收到，电脑上找不到 | 打开网页版「收到的文件」，点击下载，然后查看浏览器的下载记录。 |

## 设备查找、消息与本地 AI

- **设备查找与隐私**。网页版首次连接、软件从 build131 起首次建立身份查找资料时，默认允许通过设备名称和身份码查找，无需先点保存。已有设备保存的查找设置继续生效。软件里可以在「身份码与好友」关闭查找。网页版取消勾选后，点击「保存名称与查找设置」即可。
- **文件、文件夹与消息**。软件内可拖入文件或文件夹发送，也能给已连接的设备发消息。Windows 版使用当前系统账户加密保存聊天记录和草稿。
- **Windows 本地 AI**。可在本机分类整理收到的文件。轻量版按需下载模型，离线完整版随安装包附带模型，适合需要在无互联网环境中使用 AI 的场景。

### Windows 本地 AI 适合哪些文件整理场景？

例如从手机接收一批照片，或从其他电脑接收多份资料后，可以用本地 AI 辅助分类，减少逐个整理的操作。离线完整版随安装包附带模型，适合提前准备好软件、到现场后离线使用。轻量版适合先安装传输工具，需要 AI 时再下载模型。

## 常见问题

**连着不同的 Wi‑Fi，也能在没有互联网时传吗？**  
可以，只要两台设备在同一个可互访的内网中。比如企业的办公 Wi‑Fi 与有线网络互通，或校园的两个接入点允许设备互访。若两台设备分属独立的企业网和校园网，则需走跨网络直连。

**为什么按名字找不到对方？**  
先确认对方已连接身份服务、开启了查找，并提供当前设备的 12 位身份码。网页版和已安装的软件各自有设备身份码。遇到同名设备时，用身份码查找，再核对完整指纹。

**能先收到文件，稍后再下载吗？**  
网页版接收后可在当前浏览器的「收到的文件」里下载。准备退出临时电脑、换浏览器或清理网站数据时，请先把文件保存到自己能访问的位置。

**不想让其他人按设备名称或身份码查到我，在哪里关？**  
软件内打开「身份码与好友」调整查找开关。网页版在本机身份区域取消勾选「允许通过名称或身份码找到我」，再点击「保存名称与查找设置」。已有设备保存过的选择在更新后继续生效。

## 离线传输盒子（设计中）

计划把 USB 接入、Wi‑Fi 热点和本地传输页面集成到一个设备里。原型拟采用电脑通过 USB 接入、手机连接盒子 Wi‑Fi 的方式，由盒子建立局域网。在没有外网的地方，手机可以通过浏览器打开盒子里的传输页。按机型验证接入方式和传输表现后，再确定正式支持范围。

计划先验证三个环节。

1. **接入**。电脑识别盒子提供的 USB 网络，手机能连接盒子创建的热点。
2. **打开传输入口**。手机加入热点后，通过二维码或本地地址打开传输页面。不同设备插入 USB 后能否显示系统提示，需要实测。
3. **离线收发**。断开外网后，验证电脑和手机能否双向传文件，并核对接收结果。
